This release hands the affinity rank names back to each pet: an author can declare a `panel.ranks` ladder in `voice.json`, and the built-in whale tier names drop to a fallback (PR #22, requested in issue #21). It also fixes the trust fence leaking an exception into the host whenever the pairing service was absent, where the web server turned it into an empty-body 400 (dsh-web#1942), and moves the plugin cohort to host 0.2.1-rc.3.

> **Compatibility**: nothing breaks. The package name `@linxin666/dsh-pet`, the install path, the `$DSH_HOME/pet.json` filename with all of its keys, and every wire-protocol field keep their names and meaning. A pet that declares no `panel.ranks` renders exactly as before, and affinity points, rewards, cooldowns and the persisted ledger are untouched. The `dsh.engines.dsh` declaration and its semantics are frozen as well, but one thing does change: its floor moves from `0.2.1-rc.2` to `>=0.2.1-rc.3` in this cycle (following the supported host cohort, with both README badges updated), so an installation still on an rc.2 host needs the host upgraded to 0.2.1-rc.3 or newer first.

### New Features

- `voice.json` gains an optional `panel.ranks` affinity ladder (PR #22, requested in issue #21): each entry is `{ min, name, nameEn? }`, where `name` is the default and `nameEn` applies when the UI locale is English. A declared ladder replaces that pet's tier names whole, and the built-in 幼鲸 / 伙伴 / 挚友 / 深海羁绊 / 心有灵犀 / 传说羁绊 / 神话羁绊 / 永恒之契 / 鲸生共渡 set drops to a fallback
- Ladder validation is all-or-nothing, matching the voice pack's warn-and-drop discipline: 1-16 entries, the first `min` must be 0, strictly ascending unique minima, names of 1-24 characters. Any violation drops the whole ladder and restores the built-in names, so a bad ladder never gets the pet rejected
- The ladder is display-only: points, rewards, cooldowns, the built-in thresholds and the persisted ledger are untouched, and `panel.ranks` only changes which name `rankOf` / `affinityViewOf` resolve. `{rank}` inside `panel.stats` receives the effective name, so a custom stat format shows the pet's own tier name too
- When layers merge, a declared ladder replaces the previous layer whole and tiers are never merged across layers, because merging two partial ladders would invent thresholds no author declared. Precedence stays pet `voice.json` > global `$DSH_HOME/pets/.voice.json` > built-in, and the ladder resolves in the same place as the remark layers (`voiceLayers` / `applyVoiceLayers`), so startup, `setPetId` and the settings-surface apply cannot drift apart
- `contracts/voice-pack-v1.schema.json` documents the new block and the drift lock in `src/voice-pack.test.ts` keeps its caps in sync; the bilingual README's "Voice packs and panel DIY" row and example gain `ranks`

### Bug Fixes

- The trust fence no longer throws when the pairing service is absent (dsh-web#1942). `src/pair-access.ts` used to read `ctx.remoteWebUiPairing` as a property, which cordis answers by throwing (`cannot get property "remoteWebUiPairing" without inject`) when the service was never injected. The exception escaped the route handler and the host web server turned it into an empty-body 400, so "this composition carries no pairing service" looked like a malformed request
- `lookupPairing()` now tries the non-strict `ctx.get('remoteWebUiPairing', false)` first (an unloaded service answers undefined instead of throwing), then falls back to the property read wrapped in `try/catch`: an unreadable value counts as no pairing service, so the fence answers "not paired" instead of leaking the error into the route layer. `tests/access.spec.ts` pins both lookup paths (30 new lines)

### Other Changes

- The plugin cohort advances to 0.2.1-rc.3: the consumed `@deepseek-ai` development dependencies move to `^0.2.1-rc.3`, `dsh.engines.dsh` and the `@deepseek-ai/dsh` peer move to `>=0.2.1-rc.3`, the `packageExtensions` repairs for `dsh-client-store` / `dsh-client-ui-primitives` in `pnpm-workspace.yaml` are re-keyed to rc.3 (including the two DeepSeek utility pins), and the lockfile covers all 29 resolved rc.3 packages; the eleven-row browser platform table in `shared/web-platform.ts` is unchanged and only its provenance comment moves
- At the surface the pet consumes, those upstream changes are additive: `DraftInitializationOptions.whenDraftExists` is optional, the pet implements neither `MessageSubmissionState` nor the new conversation-header owner, and the agent and durable session event declarations used by the activity projection have no rc.3 change, so no runtime adaptation is needed
- Three new records under `.agents/notes/implemented/`: `feature/2026-10-23-pet-affinity-rank-ladders.md` (the ladder decision and the rejected options), `process/2026-10-24-sdk-cohort-0.2.1-rc.3.md` (why the cohort moved) and `process/2026-10-20-plugin-review-round.md` (this round's plugin review)
- Tests: `src/voice-pack.test.ts` pins validation and whole-ladder merge, `src/affinity.test.ts` pins lookup and the `nameEn` projection, `src/ledger.test.ts` pins the ledger re-seat, `src/service.test.ts` pins global-vs-pet precedence across a switch and a settings apply, `src/client/PetSprite.test.tsx` pins English/default rendering and a custom `{rank}` format, and `src/client/index.test.tsx` covers the mount injection; locally 681 tests in 51 files and the 22 `node --test scripts/dsh-pet*.test.mjs` tests all pass
