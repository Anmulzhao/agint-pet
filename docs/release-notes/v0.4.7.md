本版本迎来第十只宠物「鲸鱼娘·萝莉」（`jyn-loli`）——本仓库第一只由图生视频逐条生成、以 frames2d 渲染的角色，十轨 720 帧共用一条 72 帧节奏和一个 764×1172 裁切框；交付前又把她 720 帧预览 GIF 里的棋盘格预合成、`rest` 入场轨的灰影和 `work-fail` 彩虹的平涂色块一并修掉，并补上了她唯一的玩法缺陷：点击此前不触发任何加成。同时把 frames2d 的解码帧缓存从「永不释放」改为按字节预算回收，修掉了播放过多条轨道或切换皮肤后常驻内存单调增长的问题。宿主侧对齐官方 0.2.1-rc.2 SDK cohort。

> **重要变更**：声明支持的宿主下限抬到 `>=0.2.1-rc.2`（`dsh.engines.dsh`、`@deepseek-ai/dsh` 宿主 peer 与两份 README 徽章同步），更旧的宿主不再落在声明范围内；`./invariant` 子路径导出被删除（连同 `src/invariant.ts` 与两份 tsdown 配置里的条目），因为官方 0.2.1-alpha 线取消了 runtime invariant 机制、`@deepseek-ai/dsh-invariants` 不再发布，而该模块只重复校验本包自己的常量，单测已经钉住这些常量。除此之外是加法与依赖升级：包名 `@linxin666/dsh-pet`、安装方式、布局持久化位置 `$DSH_HOME/pet.json` 与键名、线协议字段都没有改名或改语义，没有需要手工迁移的步骤。

### 新功能

- 新增第十只宠物「鲸鱼娘·萝莉」（`jyn-loli`）：frames2d 渲染，10 条轨道 / 720 帧 / 每帧 40 ms，全部轨道统一 **72 帧 × 40 ms = 2880 ms** 节奏，并共用同一个 764×1172 裁切框，切换状态时角色既不跳大小也不跳位置；带 `stats`、4 个待机小动作（挠头 / 抱鲸鱼枕头 / 舔棒棒糖 / 踏拍摇摆）、三个触摸区、打工与五成成功率的两条结果轨、躺下休息与躺平时的能量回复、被动收入与商店，以及每条轨道一张预览 GIF。由 `stushansusu`（涂山苏苏）以 MIT 授权投稿，与 `assets/jyn`、`assets/jyn-foxtail` 同属「鲸鱼娘」角色线（#16）
- 她的 84 MB 内容与 `jyn` / `jyn-foxtail` / `doro` 一样**不进** `package.json` 的 `files` 白名单：只在仓库内随市场分发，`@linxin666/dsh-pet` 的安装体积不变

### 修复

- frames2d 的解码帧不再永久常驻：改为在 `MAX_RETAINED_BYTES`（128 MiB）内按 Map 插入序做 LRU 回收。此前解码缓存只清理失败路径，任何播放过的帧都要到 dispose 才释放，一只三皮肤宠物跨轨循环下来可钉住约 1.7 GB 内存且只增不减；现在正在播放轨的前瞻窗口与下一次绘制正在等待的那帧永远不会被驱逐，回收优先取出别的轨道，dispose 同步释放全部保留位图，迟到的解码结果也会自己关闭
- `jyn-loli` 的 720 帧预览 GIF 改为真透明：此前由预合成的棋盘格产出，整帧不透明、角落读到 (239,237,240)；重录后角落 alpha 为 0，叠白背景与已提交帧的平均差从 17 降到 2.0–2.5/255
- `rest` 入场轨不再带灰色重影：源片 f0..f20 改为 1:1 逐帧照搬（不再线性插值），多出来的 27 帧落在躺定之后几乎不动的呼吸段，被标记区间的重影幅度从 24.8 降到 2.5 灰阶，`rest` → `resting` 接缝仍为 0
- `work-fail` 的彩虹改为羽化半透明叠加：被它盖住的像素从时间上最近、并未覆盖它们的帧取回（扇形并集 100% 可找回），毛衣细节恢复 55%，不再有整块平涂纯色埋掉毛衣与鲸鱼图案
- 修掉她唯一一处玩法缺陷：`clickBoost` 原本挂在并不存在的三条 shy 动画轨上，触摸块因此整块被丢弃，宿主的回应是 `{"ok":false,"error":"no-touch"}`——她是当时唯一一只点击不给数值的 frames2d 宠物；现在触摸区、其效果与台词保留，`clickBoost` 改挂 `stats` 块

This release adds the tenth pet, the whale girl's loli form (`jyn-loli`) - the first pet in this repository whose frames are generated track by track from image-to-video and rendered through frames2d: ten tracks, 720 frames, one shared 72-frame cadence and one 764x1172 crop box. Before it shipped, its 720 preview GIF frames lost the checkerboard pre-composite, the `rest` entry track lost its grey ghost, and the `work-fail` rainbow stopped burying the sweater; its one gameplay defect is fixed too, a tap that used to feed nothing. The frames2d decode cache also stops growing forever: it is now reclaimed under a byte budget. On the host side the package aligns with the official 0.2.1-rc.2 SDK cohort.

> **Important change**: the declared host floor rises to `>=0.2.1-rc.2` (`dsh.engines.dsh`, the `@deepseek-ai/dsh` host peer and both README badges together), so older hosts fall outside the declared range; the `./invariant` subpath export is gone (with `src/invariant.ts` and the entries in both tsdown configs), because the official 0.2.1-alpha line removed the runtime invariant mechanism and `@deepseek-ai/dsh-invariants` is no longer published, while that module only re-checked this package's own constants, which the unit tests already pin. Everything else is additive or a dependency upgrade: the package name `@linxin666/dsh-pet`, the install path, the layout persisted in `$DSH_HOME/pet.json` with its keys, and every wire-protocol field keep their names and meaning, so no manual migration is needed.

### New Features

- New tenth pet, the whale girl's loli form (`jyn-loli`): frames2d rendering, 10 tracks of 720 frames at 40 ms each, every track on one **72-frame x 40 ms = 2880 ms** cadence and cut from the same 764x1172 box, so the character neither jumps size nor position when the state changes. It carries `stats`, four idle-director acts (scratch head, hug a whale pillow, lick a lollipop, sway on the beat), three touch zones, work with two result tracks behind a 50% roll, lying down to rest with energy regen while lying, passive income, a shop, and one preview GIF per track. Contributed by `stushansusu` under MIT, on the same whale-girl character line as `assets/jyn` and `assets/jyn-foxtail` (#16)
- Its 84 MB of content stays **out** of the `package.json` `files` whitelist, like `jyn` / `jyn-foxtail` / `doro`: it ships from the repository through the market only, so the installed size of `@linxin666/dsh-pet` is unchanged

### Bug Fixes

- frames2d no longer retains decoded frames forever: the cache now reclaims under `MAX_RETAINED_BYTES` (128 MiB) in Map insertion (LRU) order. The decode cache used to prune only its failure path, so any frame that ever played stayed resident until dispose, and a three-skin pet cycling across its tracks pinned roughly 1.7 GB with monotonic growth. The playing track's look-ahead window and the frame a draw is awaiting are never evicted, other tracks are reclaimed first, dispose releases every retained bitmap synchronously, and a decode that lands after dispose closes its own frame
- The 720 preview GIF frames of `jyn-loli` are truly transparent again: they came out of a pre-composited checkerboard, fully opaque with a corner reading (239,237,240). Re-recorded, the corner alpha is 0 and a frame composited on white differs from its committed frame by a mean of 2.0-2.5/255 instead of 17
- The `rest` entry track no longer carries a grey ghost: source frames f0..f20 are copied 1:1 frame for frame instead of linearly interpolated, and the extra 27 frames land on the quiet breathing that follows the lie-down, so the ghost amplitude in the flagged range falls from 24.8 to 2.5 grey levels while the `rest` to `resting` seam stays exactly 0
- The `work-fail` rainbow is a feathered translucent overlay: pixels it covered are restored from the nearest frame that does not cover them (100% of the fan's union is recoverable), sweater detail comes back at 55%, and no flat pure-colour bucket buries the sweater and its whale pattern any more
- Its one gameplay defect is fixed: `clickBoost` was gated on three shy animation tracks the package does not ship, so the whole touch block was dropped and the host answered a tap with `{"ok":false,"error":"no-touch"}` - she was the only frames2d pet in the set whose clicks fed nothing. The touch zones, their effects and their phrases stay, and `clickBoost` is gated on the `stats` block instead

### Other Changes

- Aligned with the official 0.2.1-rc.2 SDK cohort: every `@deepseek-ai` devDependency moves from `^0.2.1-alpha.5` to `^0.2.1-rc.2`, cordis `~4.0.5` and schemastery `~3.18.5` match the stable releases the cohort declares, `pnpm-lock.yaml` is rebuilt from a fresh resolution, and `minimumReleaseAgeExclude` is reduced to the resolved set
- `shared/web-platform.ts` re-verifies the frozen module table of the 0.2.1-rc.2 dist: byte-identical to alpha.5, so only the verification note changed. The `dsh-agent` `AssistantStreamFrame` and the `dsh-session` event vocabulary are likewise identical across the two lines
- README: the bilingual built-in pet table gains the `jyn-loli` row, and `README.i18n.yaml` re-records the pair hashes
- New PR evidence directory `docs/pr-evidence/jyn-loli-pr-16/` (the Settings pet selectors, the pet card, the selector's unmodified option list, and the running host's own registry read)
- Agent Notes: the `jyn-loli` frames2d decision and its frame-level findings, the frames2d retention-budget decision, the 2026-10-12 / 10-13 / 10-16 pet review rounds, and the 0.2.1 cohort migration
- Tests: a new `tests/jyn-loli-pet.spec.ts` (including a dependency-free GIF89a decode guard, because a checkerboard GIF and a transparent one share headers, frame counts and cadence) and frames2d retention-budget release cases
