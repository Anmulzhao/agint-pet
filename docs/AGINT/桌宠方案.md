# AGINT 桌宠方案

- 日期：2026-10-04
- 状态：可执行
- 适用仓库：本 fork（`Anmulzhao/agint-pet`），基线 commit `36f605619bdf5445e84493b7faaf2bbb51077b14`
- 关联提案：`5536e0ec`（v5 总方案）、`d276e054`（许可分支）

本文件是 AGINT 桌宠的实施方案。提案在 evolve 存储里，本文件是可执行版本。

## 1. 这个 fork 存在的理由

上游 `dsh-pet` 已经装在这台机器上并且在跑。本 fork 不改它的功能，只做两件事：

1. **剔除 4 个受限内置资产**，让这个仓可以对外分发。
2. **作为 AGINT 桌宠的上游基线**，以后要改宠物插件行为时在这里改，不改上游。

不做的：改宠物玩法、改渲染器、加 AGINT 逻辑进 `src/`。

## 2. 架构：分三块

| 块 | 位置 | 许可 | 状态 |
|---|---|---|---|
| 宠物插件本体 | 本 fork | Apache-2.0 | 已挂载，运行中 |
| AGINT 状态源 | `DSH-AGINT/plugins/agint-mascot` | MIT | 未开工 |
| AGINT 宠物资产 | `$DSH_HOME/pets/agint/` | MIT 或 CC0 | 未开工 |

**AGINT 代码不进本 fork。** 状态源做成 AGINT 仓里的独立插件，跨插件调 `ctx.pet.announce()`。这是宿主既定模式，见 `README.zh.md` 第 216 行。

理由三条：

1. fork 保持成上游近亲，`git fetch upstream` 加重基才不痛。
2. `DSH-AGINT` 保持 MIT，不引入 Apache-2.0 代码。
3. AGINT 逻辑混进 Apache 目录树会让每次同步都要人工判断 `LICENSE-AGINT.md` 的分类规则。

## 4. 阶段

### P1 状态源插件（下一步）

1. 在 `DSH-AGINT` 新建 `plugins/agint-mascot`。双半结构照抄 `agint-family-panel` v0.2.2。
2. host 半订阅四个状态源：`agint.cron.list()`、`agint.metrics.summary()`、`agint.selfModel.stats()`、`ctx.loader.entries()`。
3. **系统健康走 `ctx.pet.setSkin()`，不走 `announce`。** 四个皮肤：`healthy` / `degraded` / `failed` / `unknown`。
   **必须检查返回值。** 未声明的 id 只返回 `{ ok: false, error: 'unknown-skin' }`，不抛异常。
   不检查就等于状态切换全部失效且无感知。
4. 逐源降级。读不到写「未读到」，不准用 0 冒充绿。**读不到是 `unknown`（灰），不是 `degraded`（琥珀）。**
5. **`announce` 落盘纪律要分开说。** 公告确实只存内存、不落盘（`service.ts:383`，上游行为，不要改）。
   **但 `setSkin` 落盘**（`service.ts:789` `ledger.setPetSkin`）。皮肤是持久化状态，重启后保留。
6. `announce` 只用于语义天然吻合的数据：`cost` / `balance`。**系统健康与插件状态不借道。**
   轮播参数与 TTL 约束见规范第 0 节决策 1。
7. 挂载新插件要改 `$DSH_HOME/profiles/web/cordis.patch.yml` 或 agint preset，**改完要老板重启 DSH。我不自行重启。**
8. 验收：制造一个失败插件，**宠物皮肤切到 `failed`** 且返回值 `ok: true`；
   断开一个 service，皮肤切到 `unknown`（灰）而不是 `degraded`（琥珀）。

**已验证**（2026-10-04）：服务注册名是 **`ctx.pet`**（`src/index.ts:117` `export const name = 'pet'`）。
`PetService extends Service`（`src/service.ts:269`），`setSkin` 是公开 RPC（`:780`）且有 HTTP 面（`src/routes.ts:609`）。
本条不再是未验证项。

**遗留未验证**：`setSkin` 之后浏览器侧多久可见。它写 ledger，浏览器 2 s 轮询（README 第 216 行）。
**状态变化最多延迟 2 s。** 别拿来报需要即时感知的事。

### P2 AGINT 宠物资产

1. 建 `D:\DSH\agint-pet\` 源目录。
2. `petManifestVersion: 2`，`renderer: "frames2d"`，`license` 填真实授权标识（必填字段）。
3. 七条轨道对应七相位：`idle` / `waiting` / `thinking` / `tool` / `review` / `done` / `failed`。`idle` 必填。
4. **另加四个皮肤的 idle 帧**：`healthy` / `degraded` / `failed` / `unknown`。
   `healthy` 可复用原 idle 轨道，**净增 3 套**。皮肤 id 约束 `^[a-z0-9][a-z0-9-]*$`、≤ 24 字符。
   **四个皮肤必须靠姿态可区分，不能只换色。** 皮肤通道没有文字层，读屏访问不到。
5. 显示尺寸 96 px。落在 32 px 禁用档之上，且高于 64 px 的色彩清晰度门槛（规范第 2.1 节）。
6. 加 `voice.json` 换气泡文案。**人格不是新角色，是「智进」本人**（规范 v0.5 §9.0）—— 与 AGINT preset 同名同身份。
   语气基准见规范 §10.2-10.4（身份公式 + 宪法五条导出的语气规则），示例台词见 §10.5-10.7。逐池覆盖，改行不改结构。
   ⚠️ 两条硬约束：**只称「老板」、自称「我」**（§10.8 约束 5）；**失败台词必须含失败项数量或 id**（约束 7）。
7. 加 `decoration.json` 做状态装饰。**注意它按相位绑定，做不了系统健康。**
   `license` 必填，仅 webp/png，单帧 ≤ 2000 ms，cell ≤ 256，columns ≤ 16。
8. `node scripts/dsh-pet validate <dir>`。
9. 装到 `$DSH_HOME/pets/agint/`。
10. 验收：`dsh web` 启动后设置「宠物」分区能选中 AGINT，且四个皮肤都能选中。

契约约束见 `contracts/pet-manifest-v2.schema.json`：`tracks` 1–64 条、kebab、≤32 字符；`frames` 1–64 项；`frameMs` 16–5000 ms 且必须配等长 `frames`；`defaultFrameMs` 16–5000 默认 200；`tracks` 与 `phases` 在 frames2d 块里**必填**（第 246-249 行）。

**✅ 阻塞已解除（规范 v0.6，2026-10-04）。**

11 套帧 = 7 相位 + 4 皮肤 idle，净增 3（决策 2「换通道」的代价）。
形象是**参数化的**（一条不闭合单笔路径），所以：

- ❌ 旧路径：手绘 11 张画 → 需要美术
- ✅ 已走通：**1 份参数表 + 1 个渲染脚本** → `tools/zhijin-frames/render.cjs`

### P3 语音通道

现状与 v5 提案写的不一样。更新如下。

1. `$DSH_HOME/speech-to-text/sensevoice/models/` 下有 `sensevoice-onnx/model.int8.onnx`（239 MB）、`tokens.txt`（316 KB）、`silero/silero_vad.onnx`（1.8 MB）。**模型在盘上。**
2. `$DSH_HOME/profiles/web/node_modules/@linxin666/` 的装包清单里没有语音类包。`cordis.patch.yml` 的插件行里也没有。**我没有找到使用这些模型的插件。**
3. 上游 `dsh-pet` 不提供语音 I/O。`src` 全量 grep `getUserMedia` / `SpeechRecognition` / `speechSynthesis` / `audio` 命中 0。
4. `voice.json` 是文字气泡包，不是 TTS。

三选一，需要老板定：

| 方案 | 做什么 | 风险 |
|---|---|---|
| A 接现成模型 | 写一个 AGINT 插件调 SenseVoice + Silero VAD | 模型来源与版本我不清楚 |
| B 等上游语音插件 | 找上游有没有 speech 包 | 本机没装，不知道上游有没有 |
| C 从零 | 自己接 ASR | 工作量最大 |

无论选哪个，先做：

1. 写隐私红线：默认不录制、不落盘、不外传。录音只在按键说话期间存在内存。
2. 语音只做发起，最终动作照走 `rule_check` 门禁。
3. 唤醒词放最后。
