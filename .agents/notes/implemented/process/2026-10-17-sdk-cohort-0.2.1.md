# Agent Note: Adapt the plugin to the official 0.2.1 SDK cohort

Status: implemented

## Problem

The family approved moving this repository from the 0.1.7-rc.1 SDK cohort to
the 0.2.1 line, landing on 0.2.1-rc.2 (0.2.1-rc.1 was never pinned; this
branch first adapted to 0.2.1-alpha.5 and then advanced to rc.2 when the
official host and npm caught up). Three cohort facts had to be reconciled at
once:

- The 0.2.1-alpha line removed the official runtime invariant mechanism:
  `@deepseek-ai/dsh-invariants` was last published at 0.2.0-rc.2, does not
  exist on the 0.2.1 line, and the SDK packages no longer carry their
  `./invariant` export or peer. This package still shipped a `./invariant`
  subpath (`src/invariant.ts`, a `package.json` export, and entries in both
  tsdown configs) that mirrored the retired pattern.
- The cohort's coupled peer set moved: every SDK package now peers
  `@deepseek-ai/cordis ~4.0.5` and `dsh-settings` peers
  `@deepseek-ai/schemastery ~3.18.5` — stable releases, no longer
  4.0.5-alpha.2 / 3.18.5-alpha.2 — while this repository declared
  `cordis ^4.0.4` (devDependency) and `schemastery ^3.18.4` (dependency).
- The shell's frozen browser module table grew during the 0.2.1 line: the
  `dsh-web-frontend` dist seeds `zod` and `@tanstack/react-virtual` in
  addition to the nine rows `shared/web-platform.ts` mirrored from 0.1.7-rc.1.

## Decision

**Manifests.** Every `@deepseek-ai` devDependency now sits at `^0.2.1-rc.2`.
The declared host floor moved with the cohort in both surfaces that carry it:
`dsh.engines.dsh` and the `@deepseek-ai/dsh` host peer, both `>=0.2.1-rc.2`,
and both README badges carry the same literal.

**Coupled peers moved too, at the cohort's own ranges.** `cordis` is
`~4.0.5` and `schemastery` is `~3.18.5` — the exact ranges every SDK package
and `dsh-settings` peer, and the exact versions the host installs. Leaving
either behind would pin dev-time types one cohort old and, for schemastery,
invite a second module copy next to the host's own instance — the
shadow-copy identity class.

**The legacy `./invariant` surface is deleted, not kept.** `src/invariant.ts`,
the `package.json` export, and the `src/invariant.ts` entries in
`tsdown.config.ts` / `tsdown.prepare.config.ts` are removed, and the stale
package-invariants reference in the `shared/tsdown.client.ts` `libEntry`
comment went with them. The module only re-checked this package's own
constants (affinity bounds, cooldown ordering, phase-to-animation mapping) at
import time; those constants stay pinned by the unit tests that already
exist.

**`pnpm-workspace.yaml` is rebuilt, not appended.** The packaging-defect
`packageExtensions` are re-verified against the 0.2.1-rc.2 tarballs
(`dsh-client-store` and `dsh-client-ui-primitives` still declare no runtime
dependencies; the primitives set carries `@deepseek-ai/dsh-util-code-language`,
which the emitted lib imports, mirroring the family ledger) and are keyed to
the cohort. `minimumReleaseAgeExclude` names the exact set this tree resolves
— the `@deepseek-ai` packages at 0.2.1-rc.2 plus `cordis 4.0.5`,
`cordis-plugin-loader 1.0.6`, `cosmokit 1.8.6`, and `schemastery 3.18.5` —
with no stale lines from earlier cohorts.

**The platform mirror is updated.** `shared/web-platform.ts` adds `zod` and
`@tanstack/react-virtual`, verified in the 0.2.1-rc.2 dist bundle's
`staticModules` table (byte-identical to the alpha.5 one); the comment
records the verification cohort.

**One API adaptation.** `dsh-client-ui-settings@0.2.1` dropped
`mode: 'host' | 'memory'` from `ConfigFormSnapshot` (memory mode retired). The
pending-snapshot literal in `src/client/index.ts` and the stub in
`tests/pet-section.spec.tsx` drop the field.

## Alternatives considered

**Keep `cordis` / `schemastery` at their old ranges.** They were not named in
the cohort-order list, but the SDK peer set moved; keeping them would leave
dev-time types behind the host runtime and, for schemastery, risks a profile
tree carrying two schemastery copies whose `Schema` identities differ.

**Keep `./invariant` as a self-check.** The checks asserted only this
package's own constants, which the unit tests already pin; keeping the export
also advertised an official mechanism the host no longer runs.

**Rewrite the historical release notes that mention 0.1.7-rc.1.** They record
what those releases did at the time; the floor surfaces and this note own the
current-cohort statement, so history stays as written.

## Consequences

The host floor is `>=0.2.1-rc.2`: the plugin refuses older hosts, which is
the intended contract. The consumed vocabulary review found the dsh-agent
`AssistantStreamFrame` (start/chunk/end; `reasoning-delta` / `text-delta`
chunks) and the durable dsh-session events the pet projects
(`turn/start`, `step/start`, `assistant/message`, `tool/call`, `tool/result`,
`turn/end` with `TurnEndReasonMap`) byte-identical from 0.1.7-rc.1 through
0.2.1-rc.2 — no projection change, and `tests/service-enabled.spec.ts`
remains the compile-time contract pinning that vocabulary. Validation on the
rc.2 cohort: `pnpm install --prefer-offline`, `pnpm typecheck`, `pnpm build`,
the `scripts/dsh-pet*.test.mjs` node gates, and `pnpm test` all pass in the
isolated worktree. A profile installing this package needs the host already
on the 0.2.1-rc.2 cohort; profile shadow-copy acceptance against the local
host is tracked by the family's upgrade rollout, not this repository.
