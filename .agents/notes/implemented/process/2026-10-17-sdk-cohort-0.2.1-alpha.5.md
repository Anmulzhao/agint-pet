# Agent Note: Adapt the plugin to the official 0.2.1-alpha.5 SDK cohort

Status: implemented

## Problem

The family approved moving this repository from the 0.1.7-rc.1 SDK cohort to
0.2.1-alpha.5 (0.2.1-rc.1 explicitly out of scope). Three cohort facts had to
be reconciled at once:

- The 0.2.1-alpha line removed the official runtime invariant mechanism:
  `@deepseek-ai/dsh-invariants` was last published at 0.2.0-rc.2, does not
  exist at 0.2.1-alpha.5, and the SDK packages no longer carry their
  `./invariant` export or peer. This package still shipped a `./invariant`
  subpath (`src/invariant.ts`, a `package.json` export, and entries in both
  tsdown configs) that mirrored the retired pattern.
- The cohort's coupled peer set moved: every SDK package now peers
  `@deepseek-ai/cordis ~4.0.5-alpha.2` and `dsh-settings` peers
  `@deepseek-ai/schemastery ~3.18.5-alpha.2`, while this repository declared
  `cordis ^4.0.4` (devDependency) and `schemastery ^3.18.4` (dependency).
- The shell's frozen browser module table grew: the 0.2.1-alpha.5
  `dsh-web-frontend` dist seeds `zod` and `@tanstack/react-virtual` in
  addition to the nine rows `shared/web-platform.ts` mirrored from 0.1.7-rc.1.

## Decision

**Manifests.** Every `@deepseek-ai` devDependency moves `^0.1.7-rc.1` ->
`^0.2.1-alpha.5`. The declared host floor moves with the cohort in both
surfaces that carry it: `dsh.engines.dsh` and the `@deepseek-ai/dsh` host peer,
both now `>=0.2.1-alpha.5`, and both README badges move to the same literal.

**Coupled peers move too, at the cohort's own ranges.** `cordis` becomes
`~4.0.5-alpha.2` (the exact range every SDK package peers) and `schemastery`
becomes `~3.18.5-alpha.2` (the range `dsh-settings` peers, and the range the
host itself installs). Leaving either behind would pin dev-time types one
cohort old and, for schemastery, invite a second module copy next to the
host's own instance — the shadow-copy identity class.

**The legacy `./invariant` surface is deleted, not kept.** `src/invariant.ts`,
the `package.json` export, and the `src/invariant.ts` entries in
`tsdown.config.ts` / `tsdown.prepare.config.ts` are removed, and the stale
package-invariants reference in the `shared/tsdown.client.ts` `libEntry` comment
goes with them. The module only re-checked this package's own constants
(affinity bounds, cooldown ordering, phase-to-animation mapping) at import
time; those constants stay pinned by the unit tests that already exist.

**`pnpm-workspace.yaml` is rebuilt, not appended.** The packaging-defect
`packageExtensions` are re-verified against the 0.2.1-alpha.5 tarballs
(`dsh-client-store` and `dsh-client-ui-primitives` still declare no runtime
dependencies; the primitives set gains `@deepseek-ai/dsh-util-code-language`,
which the emitted lib now imports, mirroring the family ledger) and re-keyed
to the new cohort, dropping both 0.1.7 keys. `minimumReleaseAgeExclude` is
rebuilt to the exact set this tree resolves — 29 packages at 0.2.1-alpha.5
plus `cordis 4.0.5-alpha.2`, `cordis-plugin-loader 1.0.6-alpha.2`,
`cosmokit 1.8.6-alpha.2`, and `schemastery 3.18.5-alpha.2` — removing every
stale 0.1.7-rc.1 line (including `dsh-invariants`, which no longer publishes)
and entries this tree never resolved.

**The platform mirror is updated.** `shared/web-platform.ts` adds `zod` and
`@tanstack/react-virtual`, verified in the 0.2.1-alpha.5 dist bundle's
`staticModules` table; the comment records the new verification cohort.

**One API adaptation.** `dsh-client-ui-settings@0.2.1-alpha.5` dropped
`mode: 'host' | 'memory'` from `ConfigFormSnapshot` (memory mode retired). The
pending-snapshot literal in `src/client/index.ts` and the stub in
`tests/pet-section.spec.tsx` drop the field.

## Alternatives considered

**Keep `cordis` / `schemastery` at their old ranges.** They are not named in
the cohort-order list, but the SDK peer set moved; keeping them would leave
dev-time types behind the host runtime and, for schemastery, risks a profile
tree carrying two schemastery copies whose `Schema` identities differ.

**Keep `./invariant` as a self-check.** The checks asserted only this
package's own constants, which the unit tests already pin; keeping the export
also advertised an official mechanism the host no longer runs.

**Rewrite the historical release notes that mention 0.1.7-rc.1.** They record
what those releases did at the time; the floor surfaces and this note own the
current-cohort statement, so history stays as written.

## Consequences

The host floor is `>=0.2.1-alpha.5`: the plugin refuses older hosts, which is
the intended contract. The consumed vocabulary review found the dsh-agent
`AssistantStreamFrame` (start/chunk/end; `reasoning-delta` / `text-delta`
chunks) and the durable dsh-session events the pet projects
(`turn/start`, `step/start`, `assistant/message`, `tool/call`, `tool/result`,
`turn/end` with `TurnEndReasonMap`) byte-identical between 0.1.7-rc.1 and
0.2.1-alpha.5 — no projection change, and `tests/service-enabled.spec.ts`
remains the compile-time contract pinning that vocabulary. Validation on the
new cohort: `pnpm install --prefer-offline`, `pnpm typecheck`, `pnpm build`,
and `pnpm test` all pass in the isolated worktree. A profile installing this
package needs the host already on the 0.2.1-alpha.5 cohort; profile
shadow-copy acceptance against the local host is tracked by the family's
upgrade rollout, not this repository.
